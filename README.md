# dsh-context-cleaner

给 [DeepSeek Harness](https://github.com/deepseek-ai) 用的会话上下文清理面板。侧栏点开，选一个会话，看它占多少、里面都是什么，再把不要的部分删掉——每次动文件前先备份，出问题一键还原。

## 它解决什么问题

大会话迟早会碰到这三种状况，本质是一件事：

- **请求体超窗**：`INVALID_REQUEST … the body ITSELF exceeds the window`，会话直接跑不动
- **文件太大**：几十 MB 的会话，打开慢、报错时难修
- **压缩账失效**：装了 `billion-context` 这类压缩插件时，一旦账漂移/被重置，就得按**原文**重发，本来靠折叠撑着的会话立刻爆

清理只是手段，目的是让会话的**最坏情况**也落在窗口内。

## 依赖

| 依赖 | 必需性 | 说明 |
| --- | --- | --- |
| DSH `>= 0.2.1-rc.2` | 必需 | 需要 Web GUI 与 `webServer` 槽位 |
| Node `>= 22` | 必需 | 用到 `node:sqlite`、`zstdCompressSync` |
| `billion-context` | 强烈建议 | 百分比、折叠记忆、压缩账相关功能都依赖它；没装时这些功能不可用 |
| 宿主离线校验器 | 强烈建议 | 写盘前的最后一道关卡，见下文 |

## 目录结构

```
index.js        入口：注册 /dsh-context-cleaner 路由与 ctx_dedupe 工具，导出 __test
client.js       面板（React，按需加载）
lib/base.mjs    路径/常量/日志/状态容器（会话 API、账库句柄）
lib/io.mjs      会话日志读写（多帧 zstd 解析、逐帧压缩、宿主校验器调用）
lib/sessions.mjs 列会话、读标题/首句、工作区名还原、归档与工人过滤
lib/analysis.mjs 分段、占用估算（usage 优先）、分析结果组装
lib/ledger.mjs  压缩账：账本键（含 |sub: 子车道）、取记忆块、过闸（780K）
lib/inject.mjs  重复系统注入的识别、统计、折叠
lib/backup.mjs  备份/修剪/还原、活会话拦截、待重启标记
lib/table.mjs   构成表文件模板、提示词、md 表解析、表视图持久化
lib/ask.mjs     往会话里投递提问并等回话（进程内 followup / HTTP RPC）
lib/clean.mjs   重建（窗口裁剪、坐标清理、轮步重编）、去重、按区间清除
lib/ops.mjs     清旧轮、折叠记忆替换
lib/transfer.mjs 复制记录、转移记录（新建会话后删原段）
lib/api.mjs     HTTP 路由分发、ctx_dedupe 工具注册
```

## 安装

```bash
# 从 GitHub 装
dsh plugin install github:<用户名>/dsh-context-cleaner

# 或本地开发（profile 里做 junction 后重启）
dsh plugin install link:/绝对路径/dsh-context-cleaner
```

装完**重启 DSH**（只关窗口不算），侧栏会出现「清上下文」图标。

## 面板怎么用

**选会话**：列表按占用百分比排序，带「N 轮」和文件大小。百分比 = 实际出网体积 ÷ 窗口 1048K；带 `·压` 表示取自压缩账，带 ⚠ 表示压缩账一旦失效、按正文重发会超 700K（超窗风险）。

**整理上下文构成**：给那个会话投一条指令，让它自己按工作内容列表（插件先把表头写进 `备份根/构成表/<会话>.md`，会话填行，插件再读回来）。行怎么分由会话定，列不许改。

拿到表之后，可以按行选操作：

| 操作 | 做什么 | 原会话 | 要不要重启 |
| --- | --- | --- | --- |
| 工具结果 | 选中段落的工具结果正文换成占位符，调用本身保留 | 改 | 要 |
| 折叠记忆 | 把选中段之前的部分换成 `billion-context` 的压缩记忆 | 改 | 要 |
| 复制记录 | 把选中段落复制成一个新会话 | **不动** | 不要 |
| 转移记录 | 把选中段落搬成新会话，原会话里删掉 | 改 | 要 |
| 整轮删除 | 连 `turn/start`、`step/*` 一起删掉并重排轮号 | 改 | 要 |

另外两处独立功能：

- **清掉旧轮次的工具结果**：保留最近 N 轮（默认 10，面板显示总轮数），更早的工具结果换成占位
- **折叠重复注入**：把反复重贴的系统注入（记忆快照、运行上下文、system-reminder、系统提醒、技能清单等）每类留最近 5 份，其余折成一行占位

## 安全模型

这是这个插件唯一值得细看的部分：

1. **先备份，再写盘**：每次改动前把原文件复制成 `<会话>.<时间戳>.<动作>.before-*`，默认保留 10 份
2. **临时文件 + 校验**：改动写到 `<会话>.cleaning`，用宿主自己的持久化校验器跑一遍，**不通过就删临时文件、报错、不动正式文件**
3. **正在运行的会话默认拒绝**：宿主内存里有旧记录，改了会被覆盖。可以强制清理，但强制之后**必须重启**
4. **清完必须重启**：重启前不要点开那条会话，否则宿主会拿内存里的旧记录覆盖你刚清好的文件
5. **闸门**：清完如果正文仍 > 780K token（窗口 1048K，给压缩插件留余量），直接拒绝写盘——不然压缩账一失效就爆
6. **还原**：还原前也会重新校验，这份备份不通过就自动往下一份旧备份退

做不到的事也写清楚：

- 还原只能回到备份时刻，**备份之后的新对话会丢**
- 折叠记忆之后，被折叠的原文不在会话里了（只在备份里），模型以后读不到
- 没有装离线校验器时，写盘就没有最后一道关卡（面板会提示）

## 环境变量

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `CONTEXT_CLEANER_HOME` | `~/.dsh/context-cleaner` | 备份、日志、校验器所在目录 |
| `BILLION_CONTEXT_DIR` | `~/.local/share/billion-context/sessions` | 压缩账所在目录（Windows 为 `%USERPROFILE%\.local\share\…`） |
| `DSH_PERSIST_WORKER` | 自动探测 | 宿主会话格式校验器 `worker.cjs` 的路径 |
| `DSH_ROOT` | — | DSH 安装目录，用于自动探测校验器 |

### 关于校验器

校验器就是宿主自己那份 `@deepseek-ai/dsh-session-persistence-jsonl/lib/worker.cjs`，从安装目录的 `app.asar` 里取出来即可（它是 worker_threads 入口，`workerData` 收 `{path, compression:'zstd', expectedEventCount}`）。找不到时插件照样能用，但写盘前不做格式校验，会把风险留给你——尤其别在没校验器的情况下去动不认识的会话。

## 已知限制

- 只处理 zstd 压缩的会话文件（DSH 默认格式），多帧拼接的文件按帧解析
- 会话格式随 DSH 版本变化，遇到新规则可能要改插件
- Windows 路径为主，其他平台未实测（路径都用 `path.join`，理论上可移植）
